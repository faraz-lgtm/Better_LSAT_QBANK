3. Authentication (OAuth 2.0 Client Credentials Flow)

LSAC uses Azure Active Directory with the client credentials grant type. Your application must obtain an access token from Azure AD and include it in the Authorization: Bearer {token} header for all API calls.

3.1 Token Endpoint

The token endpoint is the same for both Integration and Production. This endpoint must be called using an HTTP POST request. 

POST https://login.microsoftonline.com/{{tenantID}}/oauth2/v2.0/token

3.2 Required Parameters

Parameter Required Description
grant_type Yes Must be client_credentials.
client_id Yes Provided by LSAC.
client_secret Yes Provided by LSAC.
scope Yes Use the Scope URI for the environment you are targeting.

3.3 Authorization Header Requirement

LSAC uses Azure Active Directory with the client credentials grant type. Your application must obtain an access token from Azure AD and include it in the Authorization: Bearer {token} header for all API calls. 

Authorization: Bearer {access_token}

You may reuse the same access token for API calls until it expires. Once the token has expired, your application must request a new token before making additional API requests.

Requests that do not include a valid Bearer token will be rejected with 401 Unauthorized or 403 Forbidden responses.

4. Token Retrieval Example (.NET Core)

public async Task<string> RetrieveToken()
{
    string tenantId = "tenant_id";
    string clientId = "client_id";
    string[] scopes = "scope";
    string clientSecret = "client_secret";

    string authority = $"https://login.microsoftonline.com/{tenantId}/oauth2/v2.0/token";

    IConfidentialClientApplication app =
        ConfidentialClientApplicationBuilder.Create(clientId)
        .WithClientSecret(clientSecret)
        .WithAuthority(new Uri(authority))
        .Build();

    try
    {
        AuthenticationResult ar = await app.AcquireTokenForClient(scopes).ExecuteAsync();
        return ar.AccessToken;
    }
    catch (Exception ex)
    {
        Console.WriteLine(ex.ToString());
        return null;
    }
}

5. Add/Invite Student API (POST)

Description

This API may be integrated into your website checkout process and is used to add or invite a student and link them to you as their coach.

  1. Resell/purchase the Official LSAT PrepPlus subscription as part of a required coaching package, then invite the student to create a LawHub account and link to you as a coach.
    • isPrepPlusRequired = true
    • isPrepPlusIncludedFromVendor = true
  2. Add a student and invite them to link to you as their coach when they already have an account, and link to an existing Official LSAT Prep Plus subscription (prompt shown when the student logs in to LawHub).
    • isPrepPlusRequired = true
    • isPrepPlusIncludedFromVendor = false
  3. Add a student and invite them to link to you as their coach using a pre-existing LawHub free Prep product.
    • isPrepPlusRequired = false
    • isPrepPlusIncludedFromVendor = false

Note: In addition to biographical data, vendors must pass the appropriate values for isPrepPlusRequired and isPrepPlusIncludedFromVendor in the API request body.

This endpoint can also be used with an existing student email to renew or extend coaching, and optionally renew or extend PrepPlus when applicable.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/students

Shortened Request Body

{
  "emailAddress": "studentx@abc.com",
  "firstName": "Tester",
  "lastName": "Test",
  "isPrepPlusRequired": true,
  "isPrepPlusIncludedFromVendor": true
}

Shortened Response

{
  "coachingExpirationDate": "...",
  "coachingStartDate": "...",
  "emailAddress": "STUDENTX@ABC.COM",
  "firstName": "Tester",
  "inviteDate": "...",
  "linked": false,
  "studentCoachingId": "3ef7c177-cfa9-467f-9baa-241b4cc0f280"
}

NOTE: The studentCoachingId returned in the response is the unique link identifier between each licensee and the student. This coaching ID is the preferred method by which to access updated student information and results of prep test instances that the student has completed in LawHub.

6. Upgrade Student API (POST)

The Upgrade API is used to update a specific student subscription using their studentCoachingId. Typical uses include upgrading a student from a non-PrepPlus setup to Official LSAT PrepPlus, and renewing or extending PrepPlus when subscription dates do not align with the coaching period.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/upgradeStudent/{studentCoachingId}

Shortened Response

{
  "coachingExpirationDate": "...",
  "emailAddress": "STUDENTX@ABC.COM",
  "subscriptionType": "PrepPlus"
}

7. Get Student Information (Coaching ID)

This is the recommended, preferred endpoint for retrieving current student data using studentCoachingId, which is the unique licensee-student link identifier. Use this endpoint when you need the most up-to-date coaching/subscription state for an individual student.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/students/{coachingId}

Shortened Response

{
  "studentCoachingId": "...",
  "firstName": "KHTest",
  "lastName": "LHTester",
  "subscriptionType": "PrepPlus"
}

8. Get Student Information (Email)

Retrieves student coaching IDs and related records by student email address. This can be useful when your system has an email but does not yet have a coaching ID. However, the Coaching ID endpoint above remains the preferred method for ongoing data retrieval.

Note: LSAC policy does not allow a "+" in a student's email address.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/studentEmails/{emailAddress}

Shortened Response

[
  {
    "studentCoachingId": "...",
    "firstName": "Tester",
    "lastName": "Test"
  }
]

10. Get Test Results

Retrieves test instance results from LawHub for a student identified by studentCoachingId after the student completes a test launched through your deep link. Response data includes test instance metadata, section-level details, and item responses where available.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/students/{studentCoachingId}/instances

Shortened Response

[
  {
    "testInstanceId": "...",
    "isCompleted": true,
    "sections": [
      {
        "sectionId": "AR:116",
        "responses": [ ... ]
      }
    ]
  }
]

11. External LSAC Content Access Logging (POST)

This API is required and must be called each time a student logs into a system that provides Official LSAC content. The logging event must identify the source/vendor and student so LSAC can track external content access.

Endpoint

{{BASE_URL}}/api/vendor/{vendorId}/log

Shortened Request

{
  "studentCoachingId": "...",
  "eventType": "Login",
  "eventDate": "2024-01-01T12:00:00Z"
}

12. Deep Linking

Deep linking allows a vendor to send a student directly into a specific LSAT Prep test, section, or item within LawHub. When a student completes a test instance launched via a deep link, the results become available through the Get Test Results API.

12.1 Deep Link Structure

LSAC provides deep link templates that include:

  • Vendor ID
  • Student Coaching ID
  • Test ID
  • Section ID (optional)
  • Item ID (optional)

A typical deep link format:

https://lawhub.org/prep/deeplink?vendorId={vendorId}&studentCoachingId={studentCoachingId}&testId={testId}

Additional parameters may be appended depending on the target (section, item, etc.). LSAC provides the exact deep link templates during onboarding.
